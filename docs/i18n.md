# Languages

The studio's interface speaks ten languages, chosen as the ones most used in
music production — the languages the major DAWs ship in:

| Code    | Language              | In itself          |
| ------- | --------------------- | ------------------ |
| `en`    | English               | English            |
| `es`    | Spanish               | Español            |
| `pt-BR` | Portuguese (Brazil)   | Português (Brasil) |
| `fr`    | French                | Français           |
| `de`    | German                | Deutsch            |
| `it`    | Italian               | Italiano           |
| `ja`    | Japanese              | 日本語             |
| `ko`    | Korean                | 한국어             |
| `zh-CN` | Chinese (Simplified)  | 简体中文           |
| `ru`    | Russian               | Русский            |

The switcher is at the right end of the top bar (a globe and the language's
code). The choice is kept in the browser's storage; before one is made, the
studio follows the browser's languages (`pt-PT` gets `pt-BR`, `zh-Hans` gets
`zh-CN`) and falls back to English. Dates follow the language too.

What is translated: the interface — labels, buttons, tips, hints, menus,
messages. What is not: the song itself (names you give things), what is
written into exported files (the score's PDF, the mixdown, MIDI), messages
that come from the server or the agent (the Critic's findings, the agent's
replies), and instrument and preset names from the catalog.

## How it works

Every text the interface shows has a **semantic key** — where it is and what
it is, not its wording — and the code shows it with one of three functions
from `web/src/i18n.js`:

```js
b.leaf("span", "t", "", t("topbar.export.label")); // a text
tf("format.swingPercent", [String(pct)]); // a text with values: {0}, {1}… in order
const BANDS = [tk("mixcheck.band.sub"), tk("mixcheck.band.bass")]; // keys in a table…
b.text(t(BANDS[i])); // …shown with t()
```

`web/locales/en.json` gives every key its English, and each
`web/locales/<code>.json` its translation; a key a language lacks shows in
English. The English and the chosen language load before the studio first
draws.

### Keys

- Dot-separated lowerCamelCase segments: the module first (the file's name:
  `score`, `drums`, `mixcheck`…), then the part of the interface, the element,
  and what the text is for: `.label` (shown on the control), `.title` (its tip),
  `.hint`, `.placeholder`, `.empty`, `.confirm`, `.toast.title`/`.toast.body`,
  `.option.<value>`, plural forms `.one`/`.other`. For example
  `score.ribbon.gloss.label`, `drums.section.fill.title`,
  `projects.delete.confirm`.
- **One key per meaning.** Two places share a key only when their text means
  exactly the same thing; the same English with different meanings ("Bass" the
  clef, "Bass" the band of the spectrum) gets different keys, so each language
  can say each its own way.
- Words and messages that mean the same everywhere have shared keys:
  `common.*` (actions and states: `common.delete`, `common.off`), `term.*`
  (the studio's vocabulary: `term.channel`, `term.swing`), `panel.*` (the
  panels' names), `drum.*` (drum sounds) and `format.*` (`format.barsMany`:
  "{0} bars").
- Keys are literal strings in the code (`tools/i18n.mjs` reads them there):
  for a table of labels, mark each key with `tk("…")` and show it with `t()`.
  A table that is also data (compared with the server's values, searched,
  saved) keeps its values and gets a key beside each.

Texts are whole sentences, never pieces glued together, so that every
language can order its words; where a sentence differs with a count or a
state, there is one key per case.

## Adding or changing a text

1. Pick a key, write it in the code inside `t(…)`/`tf(…)`/`tk(…)`, and add
   its English to `web/locales/en.json` (kept sorted by key).
2. Run `node tools/i18n.mjs`: it lists, for every language, the keys it is
   missing.
3. Add the translations to each `web/locales/<code>.json` (keep `{0}`-style
   placeholders, shortcuts like `Ctrl+Z` and unit symbols as they are).
   Changing what a text means? Give it a new key, so no language keeps the old
   meaning. `node tools/i18n.mjs --prune` drops the keys the code no longer
   uses, from every file.

CI runs `node tools/i18n.mjs --check`, which fails when the code uses a key
`en.json` lacks or a literal that is not a key, `en.json` has a key the code
does not use, a language misses a key or has one `en.json` lacks, or a
translation loses a placeholder; and `web/test/i18n-smoke.mjs`, which switches
through every language in a browser.

## Adding a language

Add it to `LANGUAGES` in `web/src/i18n.js` (its BCP 47 code, its name in
itself, and the key of its name, `language.<code>` (`language.ptBR`), with its English in
`en.json` and its translation in every locale), copy `web/locales/en.json` to
`web/locales/<code>.json` and translate the values, and run
`node tools/i18n.mjs --check`. The smoke test expects ten languages; update
it too.
