# Languages

The studio's interface speaks ten languages, chosen as the ones most used in
music production — the languages the major DAWs ship in:

| Code    | Language              | In itself          |
| ------- | --------------------- | ------------------ |
| `en`    | English               | English            |
| `es`    | Spanish               | Español            |
| `pt-BR` | Portuguese (Brazil)   | Português (Brasil) |
| `fr`    | French                | Français           |
| `de`    | German                | Deutsch            |
| `it`    | Italian               | Italiano           |
| `ja`    | Japanese              | 日本語             |
| `ko`    | Korean                | 한국어             |
| `zh-CN` | Chinese (Simplified)  | 简体中文           |
| `ru`    | Russian               | Русский            |

The switcher is at the right end of the top bar (a globe and the language's
code). The choice is kept in the browser's storage; before one is made, the
studio follows the browser's languages (`pt-PT` gets `pt-BR`, `zh-Hans` gets
`zh-CN`) and falls back to English. Dates follow the language too.

What is translated: the interface — labels, buttons, tips, hints, menus,
messages. What is not: the song itself (names you give things), what is
written into exported files (the score's PDF, the mixdown, MIDI), messages
that come from the server or the agent (the Critic's findings, the agent's
replies), and instrument and preset names from the catalog.

## How it works

Every text the interface shows is written in English in the code, inside one
of these functions from `web/src/i18n.js`:

```js
t("Stop and rewind"); // a text
tf("Swing {0}%", [String(pct)]); // a text with values: {0}, {1}… in order
const TIP = tk("Transpose — shift every pitched instrument…"); // marked where written…
b.attr("title", t(TIP)); // …and translated where shown
```

When the same English word means different things in different places
("Bass" the clef and "Bass" the band of the spectrum), give it a context so
each can be translated on its own:

```js
tx("spectrum band", "Bass"); // the key is "spectrum band\u0004Bass"; English shows "Bass"
const BANDS = [tk("Sub"), tkx("spectrum band", "Bass")]; // marked in a table, t() where shown
```

`tk` is for texts defined at module level (tables of labels, tip constants):
those run before the language is loaded, so they are only marked there and
translated with `t` where they are shown.

The English text is the key. `web/locales/<code>.json` maps each English text
to its translation; a missing or empty one shows in English.
`web/locales/en.json` lists every text, and is written from the code by
`tools/i18n.mjs`, which reads the literal first argument of each `t`, `tf` and
`tk` call.

Texts are whole sentences, never pieces glued together, so that every
language can order its words; where a sentence differs with a count or a
state, there is one text per case.

## Adding or changing a text

1. Write it in English inside `t(…)`/`tf(…)`/`tk(…)` (or `tx(…)`/`tkx(…)` with a context).
2. Run `node tools/i18n.mjs`: it rewrites `web/locales/en.json` and lists,
   for every language, the texts it is missing.
3. Add the translations to each `web/locales/<code>.json` (keep `{0}`-style
   placeholders, the curly quotes' role, shortcuts like `Ctrl+Z` and unit
   symbols as they are). `node tools/i18n.mjs --prune` drops texts the code no
   longer uses.

CI runs `node tools/i18n.mjs --check`, which fails when `en.json` is not what
the code says or a language misses a text, keeps one the code no longer
uses, or loses a placeholder; and `web/test/i18n-smoke.mjs`, which switches
through every language in a browser.

## Adding a language

Add it to `LANGUAGES` in `web/src/i18n.js` (its BCP 47 code, its name in
itself, and its English name inside `tk`), copy `web/locales/en.json` to
`web/locales/<code>.json` and translate the values, and run
`node tools/i18n.mjs --check`. The smoke test expects ten languages; update
it too.
